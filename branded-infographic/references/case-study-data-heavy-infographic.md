# Case study: data-heavy infographic (June 2026)

The user asked: "Make a much more detailed infographic with all the agents, what they do, which models power them, how much each of the models costs, the estimated cost per activity for the total orchestration based on the work we've already done."

I tried three approaches in sequence. This is the empirical record of what each one did, so future sessions know which to pick.

## Attempt 1 — `grok-imagine-image-quality` (single mega-prompt, 2:3 portrait)

Built a 1500-char prompt that explicitly named every agent, every model, every price, every activity cost, and the monthly total. The model produced:
- ✅ Header (correctly rendered)
- ✅ Org tree (all 3 LLM boxes, all 7 script boxes, correct hierarchy lines)
- ⚠️ Model cost table — only 4 of 6 rows rendered. Dropped `deepseek-v4-pro`, `gemma-4-uncensored`, `deepseek-v4-flash`.
- ❌ Monthly cost section — entirely missing
- ❌ Footer — entirely missing
- ⚠️ Rendered the brand name "AIPharmaXchange" correctly but the vision model later flagged `minimax-m3` and `grok-4-20-multi-agent` as "garbled" because the vision model doesn't recognize these as real models (they are real per user directive 2026-06-14, just not in the vision model's training data)

Cost: ~$0.05 + 25 sec. 60% of data lost.

## Attempt 2 — `gpt-image-2` (per user request: "can you just use the GPT Image 2 model")

Re-ran the same prompt with `gpt-image-2`. This model:
- ✅ Header (correct)
- ✅ Org tree — actually cleaner than grok-imagine, all 7 script-agent names spelled correctly
- ❌ Model cost table — **fabricated the entire content**. Listed `GPT-4o (2024-08-06)`, `Claude 3.5 Sonnet`, `Llama 3.1 405B Instruct` — none of which are in our routing. Used stale 2024-era prices (e.g., $2.50/$10.00 for GPT-4o).
- ❌ Monthly cost section — entirely missing
- ⚠️ Footer — present but minimal, just a 2-pill legend

This was the most damning finding. gpt-image-2 didn't just drop data — it **invented** data from its training prior. The 6 models I asked it to render (`Nemotron 3 Ultra 550B`, `minimax-m3`, `grok-4-20-multi-agent`, `deepseek-v4-pro`, `gemma-4-uncensored`, `deepseek-v4-flash`) are not in gpt-image-2's training set, so it substituted. This is the cardinal failure mode for data-heavy infographics generated by the image model.

Cost: ~$0.36 + 250 sec. Wrong data in 2/6 cost rows.

## Attempt 3 — Pillow composite (the canonical version)

Built a Pillow script (`generate_infographic_full.py`) that:
- Drew the org tree visually (rounded boxes, badges, hierarchy lines)
- Drew the cost tables as text (pixel-perfect)
- Drew the monthly table as text
- Drew the callout and footer
- Used a subtle watercolor wash + paper grain for the painterly feel

Iterations to fix the bugs:
1. Header title was clipping at the edges — split into 2 lines (TITLE on one row, SUBTITLE on the next)
2. SCRIPT badges were overlapping the script-agent names — moved badges to top-LEFT of the box instead of top-right
3. An empty 4th box appeared in the CTO column — actually fine, but the bus line was drawn through the boxes; moved the bus line to the OUTSIDE of the column
4. Background image (the image model's empty-box output) had its own "AIPharmaXchange" wordmark that bled through — dropped the bg image, used Pillow noise for texture instead
5. Footer was overlapping the last data row — moved footer into a dedicated 60px cream band at the bottom
6. ResearchSynthesizer was clipping in the box — widened the script boxes from 140px to 260px and used a smaller font (18pt vs 24pt)

After 6 iterations: clean output. All 10 agent names readable. All 6 cost rows correct. All 7 monthly rows correct. Total ($6.47/mo) highlighted. Callout present. Footer in dedicated band.

Cost: ~$0.01 (PIL) + ~6 sec. Pixel-perfect data.

## Generalization

The pattern is reliable: **for any artifact where the specific numbers matter, do not use the image model. Use Pillow.**

The image model is appropriate when:
- The data is decorative (e.g., "show 10 agents in a tree" without naming their costs)
- The user wants a hero image / cover
- A human will review and the artifact is for inspiration, not for shipping

The image model is inappropriate when:
- The artifact will be sent to a human reviewer as a primary deliverable
- The numbers, names, or categories are non-canonical (e.g., not in the image model's training data)
- The user is going to make a decision based on the data in the artifact
- The artifact is being included in an "Agni Agent Report" for human review

The "vision model flagged model names as fabricated" behavior in the first attempt was actually a useful diagnostic: when the user pushes back on a model name, it's usually because the model name is genuinely outside the training distribution of the model that generated the image, which is the same set of conditions that cause data fabrication.

## The hybrid pattern (when image model IS the right tool, but text is critical)

For decorative + data-bearing artifacts where the image model IS the right tool, use the Pillow-overlay hybrid:
1. Generate the image with the image model, with empty placeholder zones where text will go
2. Open in Pillow
3. Draw the text directly on top of the placeholder zones
4. Save

This is documented in `venice-api` skill under "Pillow-overlay hybrid" references and in `scripts/pillow_infographic.py`. The org-tree visual generated by `grok-imagine` was originally intended to be the visual layer of a hybrid; in this case the hybrid was rejected because the image model's wordmark bled through, but the technique is valid for cleaner image-model outputs.

## What I should have done first

The decision tree should be:
1. Is the data in the image model's training set? If unsure, assume no.
2. Is the data fidelity critical to the deliverable? If yes, use Pillow.
3. Is the artifact for human review? If yes, Pillow.
4. Otherwise, the image model is fine.

In this case, the data was 100% outside the image model's training set (custom model catalog, custom activity costs, custom agent names) AND the deliverable was an "Agni Agent Report" for human review. Both signals pointed to Pillow from the start.
