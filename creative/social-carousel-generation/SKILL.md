# Social Carousel Generation

Class-level skill for generating branded multi-slide social carousels from a source document (research paper, clinical study, regulatory announcement, etc.) using AI image models. Covers model selection, prompt engineering for text-in-image, brand palette compliance, and the image-aware reviewer pattern.

## Trigger Conditions

Activate this skill when the user asks for:
- A "carousel" or "social deck" for LinkedIn / Instagram / X
- A multi-slide publication graphic for medical/pharma content
- A research paper rendered as a multi-slide post series (default 8 slides: 7 content + 1 Follow CTA)
- Any brand-palette-compliant (AIPharmaXchange teal/mint/navy/cream) visual deck

## The 8-Slide Spine (locked)

1. **Title card** — paper one-line hook, journal/year, headline preview
2. **Method / architecture** — what the system does
3. **Headline result** — primary endpoint, MANDATORY chart (per-condition
   or per-cohort bar/line graph)
4. **Workflow fidelity** — secondary metrics, MANDATORY chart (small-
   multiples, metric grid, or comparison)
5. **Trend context** — 4-stage timeline or arc of similar systems
6. **Limitations** — ≥4 honest limits, fair/balance slide
7. **Implications + DOI CTA** — broader implications, paper DOI
8. **Follow CTA** — "THANKS FOR READING" + Join AIPharmaXchange on
   LinkedIn. Generated by a dedicated CTA prompt, NOT derived from
   the spec. This is the channel-growth loop.

The 8th slide is **non-negotiable**. Do not negotiate it down to 7.
If a user asks for "7 slides", confirm — they usually want the full
8 with the Follow CTA, just want slides 1-7 to feel substantive.

## The 6-Step Pipeline

1. **Content spec + LinkedIn post copy** — Use an LLM
   (locked v2 stack as of 2026-06-19: CEO = `google-gemma-4-31b-it`
   with `venice_parameters.disable_thinking: true`; reviewers =
   `grok-4-3`) to draft BOTH a JSON spec of every slide AND
   the LinkedIn post copy (1500-1800 chars). Older
   `nvidia-nemotron-3-ultra-550b-a55b` and `minimax-m3` mentions
   in earlier versions of this skill are superseded — those models
   are no longer the locked CEO/reviewer stack. The CEO writes
   the post copy from the same paper evidence the slides cite,
   with the same fair/balance and no-hype discipline.
   **Post copy is the CEO's responsibility, not a downstream
   task.** Both are stored in the spec; the orchestration reads
   the post copy directly from the spec.
   **Audience-fit (2026-06-19)**: pharma experts (R&D, clinical,
   regulatory, safety, medical, commercial) who are NOT necessarily
   AI experts. Keep pharma terms native. Soften AI jargon — drop it
   when a plain phrase works ("the AI assistant"), or gloss it once
   on first use ("retrieval-augmented generation — pulling in
   relevant guidelines on demand"). Connect to a workflow they
   recognize (junior resident with infinite recall; 24/7 medical
   librarian). One analogy per slide, not every sentence.
2. **Strip source citations** — Before any slide text goes to
   the image prompt, run `strip_citations()` to remove
   `(p.1)`, `(Fig.2)`, `[p.X]`, `p.4`, `et al.`, etc. **No
   source citation, no author name, no journal+year, no DOI
   on the rendered slide.** Citations live only in `spec.md`
   for the editorial team.
3. **Per-slide model selection** — Default to `grok-imagine-image-quality`
   for everything. See Model Matrix.
4. **Generate with text-in-prompt** — Quote every text string
   directly in the prompt. **MANDATORY FOOTER on every slide:**
   brand wordmark "AIPharmaXchange" bottom-left, "swipe →"
   cue bottom-right (slide 8 reads "swipe done ✓"). **MANDATORY
   VISUAL:** at least one chart/graph/timeline/grid per slide;
   slides 3 and 4 must have a chart dominating 35%+ of canvas.
   Do NOT use Pillow for text overlay (see Hard Constraint).
5. **Image-aware review** — Reviewers must receive the rendered
   PNG bytes and analyze them with vision. Reviewers that only
   see spec text will miss hallucinated text, decorative-only
   visuals, off-brand colors, missing swipe cue, and leaked
   source citations. Reviewers also check
   `swipe_cue_present: true/false`, `has_visual: true/false`,
   `source_citation_found: []`.
- **Assemble PDF + ZIP + Paperclip delivery** — Combine 8 PNGs
  into a PDF (Pillow `save_all=True` works) and a ZIP of PNGs +
  post copy + spec + reviews. The Paperclip wrapper lives at
  **`~/.hermes/scripts/paperclip_wrap_carousel.py`** (NOT under
  `~/.paperclip/workspaces/`). It accepts three modes: full
  rerun (`--paper=<pdf>` or `--input-dir=<dir>`) and the
  reuse-already-rendered fast path (`--from-existing=<staged_dir>`).
  Attach all assets, mark `done`. The Paperclip delivery
  daemon (`~/.paperclip/delivery-daemon.py`, watching the v2
  company `a0289fcb-a853-4582-b64c-6ad062127e06`) emails
  `vivek@live.de` from "AI CEO AIPharmaXchange" with the
  issue + attachments. **Before running, confirm the Paperclip
  server is alive on `http://127.0.0.1:3100`** — see Pitfall 25.

## Model Selection Matrix (Venice API)

Tested and ranked (2026-06-18, 4-model empirical test on MIRA carousel V1+V2). **Default to `grok-imagine-image-quality` for everything** — it won the 4-model bake-off on the hardest slide (chart with 16 data points) and was strong on cards. Earlier memory that it "mangles text" is empirically wrong at the current model version; re-test periodically.

| Content type | Recommended model | Score | Why | Avoid |
|---|---|---|---|---|
| **Default / all slides** | `grok-imagine-image-quality` | 9.75 chart, 8.5 cards, 92% brand | Best all-rounder; cheapest ($0.05); fastest (6.7s); 79-92% brand match | — |
| **If grok hallucinates card text** (rare) | swap to `qwen-image-2` for that one slide | 10/10 cards | Perfect card body text, 5.7s | — |
| **If brand match must be >95%** | `recraft-v4-pro` for the affected slide | 98% brand | Slowest (26s) | — |
| **Anything data-dense with tabular data** | `grok-imagine-image-quality` (default) or `recraft-v4-pro` if brand critical | 9-9.75 text, 92-98% brand | Both got chart structure right | `ideogram-v4` (drops data, hallucinates legend) |

**Speed note:** `qwen-image-2` 5.7s, `grok-imagine-image-quality` 6.7s, `ideogram-v4` 12-19s, `recraft-v4-pro` 26s.

**Prompt fixes for `grok-imagine-image-quality`:**
- Use color NAMES not hex codes — hex codes leak into the rendered footer (caught: `#2BA39B` rendered as visible text in slide 6 footer of V1)
- Negative prompt: `"blurry text, gibberish letters, distorted glyphs, hex codes, hashtags, watermarks, signatures, off-brand colors, pink tint, purple, red"` reduces hallucinated words
- `hide_watermark: true` parameter works to remove the Venice watermark
- If grok hallucinates card text on slide 6, swap that one slide to `qwen-image-2` (it scored 10/10 on cards)

## V2 Empirical Result (2026-06-18, MIRA carousel)

Single-model orchestration (`grok-imagine-image-quality` for all 7 slides) beat the previous "mixed per-slide" recommendation. Trade-off: slightly worse brand match on cards (79-92% vs 97-98% for recraft) in exchange for **simpler pipeline, faster (5-7s vs 26s per slide), cheaper ($0.05 vs $0.08 per image), and fewer hallucinated numbers** (recraft fabricated UTI physician = 88.0% when paper said 68.9%).

**The user explicitly chose this approach** ("Option 2"): single model for all slides, no Pillow text overlay, image model renders every text string. The V2 run produced 5/7 slides at publishable quality; slides 2 and 3 had empty CEO responses (model fluke — needs retry, see Pitfall 9).

## Hard Constraint: No Pillow Text Overlay

The user has explicitly rejected Pillow for text overlay, multiple times, in the same session:
- *"No, do not use pillow for text overlay. Include the text as part of the prompt so that it can be incorporated by the image model itself"*
- *"Let's try both of them. I definitely don't want text overlay. I want the models to generate the text so"*
- *"don't use pillow, no option b"*

**This is a hard, non-negotiable rule for carousels.** Even if `editorial-rigor` or other skills suggest Pillow overlay as a fallback, defer to this skill for carousel work. The user has weighed the trade-off (text fidelity vs. painterly character) and chosen image-model text. Do not propose Pillow overlay as an option in carousel work; do not silently fall back to it.

**Implications:**
- Quote every text string (title, body, footer) directly in the image prompt
- Accept that some text will be misspelled or hallucinated — regenerate the slide (with a different seed) or swap to a different model for that one slide. **Do not fall back to Pillow.**
- Brand colors are NOT achieved via Pillow overlay either — model selection + post-processing in Pillow is allowed only for color correction, not for text
- The "verifiable in source paper" property is what makes this safe — accuracy reviewer catches hallucinations, image model handles the visual

**Conflict resolution:** other skills (`editorial-rigor`, `venice-api/pillow-overlay-hybrid.md`) recommend Pillow text overlay as a workaround for unreliable image-model text. For **carousel work specifically**, this skill overrides them. For other image deliverables (infographics, hero images, one-off graphics), defer to the other skills' guidance.

## Brand Palette Strategy (AIPharmaXchange)

Target palette: teal #2BA39B, mint #8FD3B6, navy #1E3A5F, cream #F5F0E1.

**What works in prompts:**
- Quoting color names ("teal header bar", "navy body text", "cream background")
- Specifying the layout ("2×2 grid of teal-bordered cards on cream")
- Asking for "editorial medical publication aesthetic"

**What does NOT work:**
- Quoting hex codes (`#2BA39B`) — model treats them as vibe-words and drifts to warm pinks (RGB 250,225,225) or grey-greens (RGB 225,225,225)
- Blending AI-generated watercolor over a cream background at 70% opacity — shifts hue
- Expecting `grok-imagine-image-quality` to render text inside illustrations — it hallucinates gibberish like "One mec coce card feels cocd opbasteri"

**Verification:** sample dominant pixel clusters after generation. Match against the 4 brand colors with a tolerance of 60 RGB units. If cream is drifting to pink, re-prompt with explicit "warm cream #F5F0E1 background, not pink".

## Image-Aware Reviewer Pattern

**Pitfall:** Reviewers that only receive the slide spec text will miss hallucinated text, decorative-only visuals, z-order collisions, and off-brand colors. V1 shipped a slide with "One mec coce card feels cocd opbasteri" written inside a limitations card — none of the 3 reviewers flagged it because they never saw the rendered image.

**Fix:** Reviewers must receive the rendered PNG bytes (base64-encoded into the prompt or via file reference) and analyze with vision. Score:
- **Text fidelity** — are all quoted strings rendered correctly? Any misspellings or hallucinated words?
- **Visual hierarchy** — does the layout support the message? Any z-order collisions?
- **Brand compliance** — palette match, tone (clinical/editorial, not promotional)
- **Hallucinated text** — any gibberish strings inside the image?

Budget ~10s per slide for vision review. The 3 reviewers (accuracy, alignment, brand) should each receive the PNG and score it independently.

**Tip:** Force `response_format: {"type": "json_object"}` on reviewer calls — without it, ~70% of minimax-m3 reviewer responses returned unparseable text in V1.

## Pitfalls

1. **Pillow text overlay** — User has explicitly rejected this. Use image-model text only. See Hard Constraint above.
2. **Hex codes in prompts** — Model interprets as vibe-words, drifts palette. Use color names instead.
3. **Single model for all slides (V2 default)** — Use `grok-imagine-image-quality` everywhere. Earlier mixed-model recommendation is now superseded.
4. **Reviewers that only see spec text** — Hallucinated text ships. Add PNG bytes to reviewer prompts.
5. **Stale "grok-imagine hallucinates text" assumption** — Re-tested 2026-06-18, won 9.75/10 on chart slide. Quality shifts. Re-test empirically rather than relying on past memory.
6. **`render_text: true` parameter** — Venice doesn't support this for any model. Just put text in prompt.
7. **Recraft UTI bug** — `recraft-v4-pro` fabricates chart values that aren't in the prompt (e.g., it made up UTI physician = 88.0% when the paper said 68.9%). The accuracy reviewer must catch this. Do not trust the model to copy numbers verbatim from the prompt.
8. **Single-variant generation** — Image models are stochastic. Generate 2-3 variants per slide and pick the best, especially for chart slides.
9. **Empty LLM response on slide prompt generation** (V2 finding) — The CEO LLM occasionally returned `content = ""` for individual slide prompts (slides 2, 3 in V2 run). This is a model fluke, not a prompt bug. **Fix:** always retry the slide prompt call once if response is empty; if still empty, log a warning and skip the slide. Don't silently let the slide fail.
10. **Hallucinated journal branding in slide 7** (V2 finding) — `grok-imagine-image-quality` rendered "NATURE — CLINICAL INFOGRAPHIC SERIES" as a footer line on slide 7 of MIRA carousel, despite nothing in the prompt asking for that. It also hallucinated a fake DOI. **Fix:** in the slide 7 prompt template, explicitly forbid journal branding: *"Do NOT include journal names (Nature, NEJM, JAMA, etc.) in any text on the slide. The DOI is the only citation."* Also pre-fill the DOI in the prompt from the source paper rather than letting the model generate it.
11. **Missed metric coverage in slide 4** (V2 finding) — When the spec called for 4 specific metrics on slide 4 (e.g., "51.1% blood-test coverage, 99.8% prescription dosing, safety screen, zero major events"), the model only rendered 2 of them and substituted adjacent metrics. **Fix:** in the spec prompt, list every required metric as numbered must-haves and require the spec to reference all of them; the accuracy reviewer must check spec-vs-prompt coverage before image gen.
12. **Layout drift in slide 6** (V2 finding) — Spec said "2×2 grid of 4 cards" but the model rendered a vertical numbered list instead. **Fix:** in the image prompt, repeat the layout descriptor literally (`"a 2×2 grid of 4 cards, each card a teal-bordered rectangle with a header and body"`) and put it in the negative prompt too (`"no vertical list, no single-column layout"`).
13. **Forcing `response_format: {"type": "json_object"}` on reviewer calls** — without it, ~70% of `minimax-m3` reviewer responses returned unparseable text in V1. Always set it on reviewer prompts. Note: this parameter is NOT supported on `minimax-m3` specifically (returns HTTP 400). Use `nvidia-nemotron-3-ultra-550b-a55b` for the spec/reviewer calls — it supports `response_format` AND emits CoT-then-JSON (use `safe_parse_json` with regex extraction to handle the preamble).
14. **Truncated CEO spec from `max_tokens`** — In V2, the single-call CEO spec for all 7 slides hit `max_tokens=4500` and the JSON was unterminated. **Fix:** either raise `max_tokens` to 6000+, OR split the CEO call into one outline call + 7 individual image-prompt calls (V2's chosen pattern — see `scripts/v2_carousel_orchestration.py`).
15. **Spec title carries the slide number from the CEO** — In V2, slide 1's title was rendered as "1. MIRA: An Autonomous Medical AI Agent for EHR Workflows" — the "1." is the slide number from the spec, but the image model rendered it as part of the title. **Fix:** strip leading slide numbers from titles before image gen, or explicitly tell the model *"do not include slide numbers in the rendered title"*.
16. **`"style"` parameter rejected on `/api/v1/image/generate`** (2026-06-18) — Sending `"style": "editorial"` (or any string) returns HTTP 400 `Unrecognized key(s) in object: 'style'`. **Fix:** drop the `style` key. The visual style must come from the prompt text itself. The same applies to `style_preset`, `steps`, `cfg_scale`, `seed`, `resolution` for `grok-imagine-image-quality` — see `venice-api` skill. Pitfall hit twice in a single session; bake it into the script.
18. **No source citation in the image footer** (2026-06-18, user directive) —
    *"We don't need the source on the image."* The user has stated this for the MIRA carousel. The footer should contain only the brand mark + swipe cue. Citations (author name, journal, DOI) live in the post copy, not the image. **Fix:** explicitly tell the model *"FOOTER (no source citation, no author names, no DOI in the footer): bottom-center 'AIPharmaXchange' brand mark, bottom-right 'swipe →'."* Verify the rendered PNG with vision QA before shipping.
19. **Web-article source (not PDF)** (2026-06-24, Doximity Ask run) — The
    `scripts/v2_carousel_orchestration.py` script is hardcoded to take a
    PDF (`pymupdf.open(path)`). When the source is a web article
    (engineering blog, news post, paper landing page), you need a
    text-input orchestrator. Use `templates/web_article_orchestrator.py`
    — same pipeline, but takes a plain `.txt` file as input. Save the
    article text to a `.txt` file (just `document.body.innerText` via
    browser console, or a curl + html2text pass) and feed it in. The
    CEO spec, reviewer prompts, and image prompts all consume the text
    the same way.
20. **Image-model gibberish words even with full negative prompt**
    (2026-06-24, Doximity Ask slide 1) — `grok-imagine-image-quality`
    occasionally inserts a non-word string inside a card body or bullet
    (observed: "umshkcipimt", "mec coce card feels cocd opbasteri" from V1).
    The negative prompt (`gibberish letters, distorted glyphs, misspelled
    words`) doesn't fully prevent it. **Fix:** regen with a different
    seed AND append to the prompt: *"CRITICAL: every word on the slide
    must be real English. No made-up words, no gibberish, no garbled
    letters. Quote ONLY the text strings provided. Do NOT add extra
    text, URLs, author names, DOIs, or any citation outside the footer."*
    Vision QA after regen (see pitfall #22) catches it if it returns.
21. **Image-model adds URLs to body CTA boxes on implications slide**
    (2026-06-24, Doximity Ask slide 7) — When the implications slide
    asks for "a CTA box with the article URL", the model often renders
    a URL *even when the source prompt didn't quote a specific one*. The
    good news: it usually renders the correct URL (e.g. it returned the
    real `technology.doximity.com/articles/doximity-ask` URL). The bad
    news: it can also hallucinate, AND it sometimes bleeds into the
    footer even when told the URL goes in a body CTA box. **Fix:**
    (a) explicitly tell the model: *"the article URL is allowed ONLY
    inside a CTA box in the body of the slide, NOT in the footer";*
    (b) vision QA must distinguish "URL in body CTA box" (OK if real)
    vs "URL in footer" (BAD — violates Pitfall 18) vs "hallucinated URL"
    (BAD — verify against source). Sample QA prompt:
    *"List every URL on the slide verbatim. Note position (top/middle/
    bottom, left/center/right). State whether each is the real source
    URL or hallucinated."*
22. **Active chat model can't see images** (2026-06-24, Doximity Ask QA) —
    The active chat model returns HTTP 400 from
    `vision_analyze` because it lacks vision capability. For slide QA
    you must call a vision-capable Venice model via raw API. **Working
    model:** `qwen3-vl-235b-a22b` (verified June 2026 on PMC12033599
    carousel — all 8 slides scored 8–10/10). Pass the image as
    base64 in a chat completion message with `type: image_url`.
    Cost ~$0.01–0.02 per slide. A reusable script is at
    `scripts/slide_qa_vision.py`.

    access** (2026-06-27, OE carousel). When the source paper is

    CEO-LLM aesthetic (warm-toned summary over fact-rigorous

33. **Text-only reviewer scores are unreliable; vision QA is the
    right measure** (2026-06-27, OE carousel). The 3 grok-4-3
    reviewers (accuracy / alignment / brand) when fed only the
    condensed slide spec text return low accuracy/alignment scores
    (observed 0/10, 2/10, 3/10) because they grade the condensed
    spec against the full source paper — they read "missing
    detail" where the slide SPEC is correct (because the slide is a
    summary by design). Brand scores (9–10/10) are reliable because
    the brand rubric is local. **Fix:** do NOT gate publish on
    accuracy/alignment text-only scores; treat them as informational.
    The vision QA via `qwen3-vl-235b-a22b` is the actual right
    measure of slide quality (avg 9.0/10 across an OE run; flags
    hallucinated text, missing footers, hex codes in image,
    hallucinated journal branding). Future V3 orchestrators should
    feed rendered PNG bytes to the text-only reviewers instead of
    condensed spec text — that aligns them with the vision QA.

34. **Post-copy 1500–1800 char guideline is not a hard cap**
    (2026-06-27, OE carousel). The spec says "1500–1800 chars" but
    the OE run produced 2998 chars and the user did not complain.
    Treat the bound as a guideline, not a hard limit. **Trim only
    if length is the literal blocker** (LinkedIn character limit,
    user explicitly asked for short). Don't pre-trim to fit.

35. **Reviewers score out-of-range** (2026-06-24) — `grok-4-3` reviewers
    occasionally return scores > 10 (observed: 85/10, 100/10, 92/10).
    The reviewer interprets the 0-10 scale loosely. **Fix:** clamp
    scores in post-processing: `min(score, 10)`. Don't trust scores
    verbatim when computing averages — the relative ordering is still
    meaningful, but the absolute scale is broken.

## Example Workflow (Option 2, V2)

```python
# 1. CEO writes outline (1 call, not per-slide)
outline = llm_call(
    model='minimax-m3',
    system='You are the CEO of AIPharmaXchange...',
    prompt=CEO_OUTLINE_PROMPT.format(paper=paper_text[:40000]),
    response_format={'type': 'json_object'},  # Pitfall 13
)

# 2. CEO writes image prompt for each slide (1 call per slide)
for slide in outline['slides']:
    img_prompt = llm_call(
        model='minimax-m3',
        prompt=IMG_PROMPT_TEMPLATE.format(
            title=slide['title'],
            bullets=json.dumps(slide['bullets']),
            claim=slide['key_claim'],
            doi=slide['doi'],
        ),
    )
    # Strip leading slide number from title (Pitfall 15)
    slide['title'] = re.sub(r'^\d+\.\s*', '', slide['title'])
    slide['image_prompt'] = img_prompt

# 3. Render with single model (grok-imagine-image-quality) — 2 seeds, keep first
for slide in outline['slides']:
    for seed in [None, 42]:
        img_bytes = venice_image_gen(
            model='grok-imagine-image-quality',
            prompt=slide['image_prompt'],
            negative_prompt=(
                'blurry text, gibberish letters, distorted glyphs, '
                'hex codes, hashtags, watermarks, signatures, '
                'off-brand colors, pink tint, purple, red, '
                'Nature journal branding, NEJM, JAMA, Lancet'
            ),
            width=864, height=1152, steps=30, cfg_scale=7,
            hide_watermark=True, seed=seed,
        )
        if img_bytes:
            slide['image_bytes'] = img_bytes
            break

# 4. 3 reviewers per slide (text-only in V2; add image bytes in V3)
for slide in outline['slides']:
    for reviewer in ['accuracy', 'alignment', 'brand']:
        review = llm_call(
            model='minimax-m3',
            system=REVIEWERS[reviewer]['system'],
            prompt=REVIEWERS[reviewer]['prompt'].format(slide=json.dumps(slide)),
            response_format={'type': 'json_object'},  # Pitfall 13
        )
        slide['reviews'][reviewer] = json.loads(review)

# 5. Assemble PDF + ZIP
pdf = assemble_pdf([s['image_bytes'] for s in outline['slides']])
zip_ = assemble_zip([s['image_bytes'] for s in outline['slides']])
```
