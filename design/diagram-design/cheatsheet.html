Editorial diagrams with Ox Alpha

39 diagram types · self-contained HTML + SVG · no Mermaid slop · skill installed in viv-skills/design/diagram-design

How to ask — 5 steps

  1. 1State the type (or let me pick): "architecture diagram of my app"
  2. 2List the nodes — keep it under ~9; more is two diagrams
  3. 3Name the connections and direction
  4. 4Pick a variant: light · dark · full-editorial (default: light)
  5. 5Get back a self-contained .html — open in any browser, screenshot done

Pick the right type

  • System shape → architecture, high-level, deployment, data flow
  • Logic / time → flowchart, sequence, state machine, timeline, Gantt
  • People & ownership → org chart, swimlane, process, kanban
  • Compare / decide → quadrant, radar, bar, line, scatter, treemap
  • Strategy → loop/flywheel, pyramid, venn, Wardley map, fishbone
  • Data → ER, db schema, UML class, medallion, Sankey, story map

One-liners that just work

  • "Make me an architecture diagram: frontend, backend, Postgres, Redis cache."
  • "Quadrant of Q2 projects, impact vs effort."
  • "Sequence of a bearer call with token refresh on 401."
  • "Redraw this drawio file for my deck — slide-16x9, simplified, executive." ← import mode
  • "Make this Mermaid block editorial." ← import mode
  • "Onboard diagram-design to https://mysite.com" ← brand matching, 60s

The 4 import dials (drawio / Mermaid)

  • Format: html · svg · png · html+png
  • Size: doc-inline · slide-16x9 · social-og · print-a4 · fit …
  • Detail: faithful (≤24 nodes) · balanced (≤12) · simplified (≤7)
  • Audience: engineer · mixed · executive (changes wording, not count)

Design rules it enforces

  • Density 4/10 — deletion is the highest-quality move
  • Accent color on 1–2 focal nodes only, never 5
  • Every connection must carry information — else delete the line
  • WCAG AA contrast checked automatically on brand onboarding
  • Static by default; motion is opt-in and accessible
